## Open Issues

### BUG-011 — Barcode silently set to labIdNumber

**Status:** Open — strategy not yet decided
**Scope:** Backend (`items.ts`)
**Severity:** Medium — creates silent collision risk

**Description:** When an item is created without an explicit `barcode` value, the backend silently falls back to using `labIdNumber` as the barcode. Since `labIdNumber` is user-entered and not guaranteed unique, two items could end up sharing the same barcode, breaking scan lookups.

**Impact:** `GET /items/scan/:barcode` may return the wrong item if barcode values collide.

**Pending decision:** Should barcodes be auto-generated by the system (UUID-based, guaranteed unique) or remain user-supplied? If user-supplied, uniqueness must be enforced at the DB level.
